# 용어집 (유비쿼터스 언어)

화면, 문서, 코드가 같은 말을 쓰도록 정한 기준입니다. 화면에 보이는 말은 한국어 용어를 쓰고, 코드 식별자는 아래 "코드 이름" 열을 따릅니다. 이 문서를 바꾸면 화면 문구, 문서, 새 코드 이름을 같이 맞춥니다.

## 1. 핵심 용어

| 한국어(화면) | 뜻 | 코드 이름 | 쓰지 말아야 할 말 |
| --- | --- | --- | --- |
| 업무 | 사용자가 저장해 두고 반복하거나 한 번 실행하는 자동화 한 건 | `Workflow`, `WorkflowIR` | `job`, `task` (새 코드에서) |
| 실행 | 업무 하나를 한 번 돌린 기록 | `Execution` | `run` (화면), `job` |
| 단계 | 업무 안의 한 동작(자료 읽기, 판단, 발송 등) | `Step` | `node` (화면) |
| 승인 | 외부로 내보내는 동작 전에 사람이 확인하는 요청 | `Approval` | `confirmation` |
| 트리거 | 업무를 시작시키는 조건(일정, 메일, 메시지, 웹훅, 직접 실행) | `Trigger` | `schedule` (일정 이외의 의미로) |
| 수신 기록 | 같은 이벤트를 두 번 처리하지 않으려고 남기는 기록 | `TriggerReceipt` | `dedupe`, `receipt` (화면) |
| 발견 세션 | 채팅으로 업무 후보를 찾고 확인해서 업무로 만드는 과정 | `Discovery`, `DiscoverySession` | `discovery` (화면) |
| 작업 공간 | 한 대화에 붙여 둔 자료와 그 대화의 결과 묶음 | `Workspace`, `WorkspaceSource` | `workspace` (업무 자체를 가리킬 때) |
| 연결 | 외부 서비스(Slack, Gmail, 폴더 등)에 로그인하거나 설정해 둔 상태 | `Connection` | `connector` (화면, 연결 자체를 가리킬 때) |
| 커넥터 | 외부 서비스를 호출하는 코드 어댑터 | `Connector` | `연결` (코드에서 어댑터를 가리킬 때) |
| 판단 | 여러 후보 중 하나를 고르거나 예/아니오를 정하는 결정 | `Decision` | `AI 답변` |
| 문안 | 사람이 읽을 설명·요약·본문을 쓰는 것 (LLM이 담당) | `prose` (스키마 `purpose`) | 제어 입력으로 쓰는 값 |
| Jev | 제한된 판단을 맡는 외부 판단 서비스 이름 | `jev` (경로), `JevDecision…` | `AI` 일반 |

### 구분해야 하는 짝

- **업무 ↔ 실행:** 업무는 저장된 정의(IR)이고, 실행은 그 정의를 한 번 돌린 기록이에요.
- **업무 정의 ↔ 발견 세션:** 발견 세션은 업무가 되기 전 후보와 질문을 다루는 과정이에요. 발행하면 업무가 생겨요.
- **작업 공간 ↔ 업무:** 작업 공간은 대화와 자료 묶음이고, 업무는 그 결과로 만들어진 자동화예요. 같은 작업 공간에서 여러 업무가 나올 수 있어요.
- **판단 ↔ 문안:** 판단은 값을 고르는 결정이라 실행을 좌우할 수 있어요. 문안은 사람이 읽을 글이라 실행을 좌우하면 안 돼요. 이 경계는 `workflow/ai-output-contract.ts`에서 검사해요.

## 2. 상태 이름 (집합체별 기준)

같은 뜻인데 이름이 다른 상태가 있어요. 아래 표가 기준입니다. 코드 값은 지금 그대로 두고, 새 코드와 문서는 이 표를 따릅니다.

### 실행 결과 (사용자에게 전달되는 결과)

| 상태 | 뜻 | 화면 문구 |
| --- | --- | --- |
| `success` | 끝까지 실행됨 | 실행 완료 |
| `failed` | 실행이 실패함 | 실행 실패 |
| `cancelled` | 사용자 또는 시스템이 중단함 | 실행 취소 |
| `pending_approval` | 승인을 기다림 | 승인 대기 |

### 실행 저장 상태 (DB)

| 상태 | 뜻 | 대응하는 결과 |
| --- | --- | --- |
| `running` | 실행 중 (저장 전용, 결과로 전달되지 않음) | — |
| `success`, `failed`, `cancelled`, `pending_approval` | 위 결과 상태와 같음 | 같은 이름 |

> 주의: 실행 수명주기 타입(`RunLifecycleState`)은 `completed`를 씁니다. 결과 타입은 `success`를 씁니다. 두 값은 같은 뜻으로 보고, 새 코드는 결과 타입의 `success`를 씁니다. 기존 `completed`는 이 문서에서 "성공 종료"로 읽습니다.

### 승인

| 상태 | 뜻 |
| --- | --- |
| `pending` | 사용자 확인을 기다림 |
| `processing` | 승인되어 외부 발송 중 (한 번만 잡힘) |
| `approved` | 승인되어 실행이 끝남 |
| `rejected` | 사용자가 거절함 |
| `failed` | 발송을 시도했지만 실패로 끝남 (결과 불명 포함) |

### 트리거 수신 기록

| 상태 | 뜻 |
| --- | --- |
| `processing` | 지금 처리 중 (다른 처리가 같은 이벤트를 잡지 못하게 함) |
| `completed` | 처리 끝 (재처리하지 않음) |
| `failed` | 실패. 조건을 갖추면 다시 시도할 수 있음 |
| `dead` | 재시도 한도를 넘어 더 시도하지 않음 (데드레터) |

### 업무 수명주기

| 상태 | 뜻 |
| --- | --- |
| `draft` | 만들고 있는 중 (저장 전) |
| `saved` | 저장됨 (자동으로 돌지 않음) |
| `enabled` | 트리거가 켜져 자동으로 돎 |
| `disabled` | 저장은 되어 있지만 트리거가 꺼짐 |

### 발견 세션

| 상태 | 뜻 |
| --- | --- |
| `needs_clarification` | 사용자에게 질문이 남아 있음 |
| `ready_to_publish` | 질문이 끝나 업무로 발행할 수 있음 |

(그 밖의 발견 세션 상태는 `work-discovery/schema/status.ts`를 기준으로 봅니다.)

## 3. 정해진 것과 아직 정하지 않은 것

- **정함:** 화면에는 "업무"를 씁니다. 코드에서 업무를 가리킬 때는 `Workflow`를 씁니다.
- **정함:** 새 코드에서 `job`은 쓰지 않습니다. 기존 `job-registration` 같은 이름은 그대로 두고, 새로 만드는 이름에는 쓰지 않습니다.
- **정함:** 실행 결과 상태는 `success`를 씁니다. `completed`는 수명주기 타입에만 남깁니다.
- **아직 안 정함:** `completed`와 `success`를 하나로 합칠지. 두 타입을 하나로 바꾸면 DB 값과 화면 문구가 같이 바뀌므로 별도 작업으로 다룹니다.
- **아직 안 정함:** 발견 세션(Discovery)과 업무 수명주기(Workflow lifecycle)의 관계. 발행 시점에 어떤 상태가 넘어가는지 정리가 더 필요합니다.
