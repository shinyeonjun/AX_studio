# AX Studio 프로젝트 문서

AX Studio의 제품 방향, 설계 결정, 개발 상태, 문제 해결과 릴리스 기준을 한곳에서 확인하는 문서입니다. 제품 비전은 **도구만 연결하면, 내 일을 처리하는 개인 업무 비서**입니다. Jev와 host 코드, LLM CLI를 공통 엔진으로 사용해 연결된 도구 안에서 대화·자료 검색·답변·업무 실행을 지원하는 것을 목표로 합니다.

**상태:** 개발 중. 범용 개인 비서는 목표이며 현재 제공 범위를 보장하는 문구가 아닙니다. Excel·규정 PDF의 예외 처리 흐름은 첫 인수 사례입니다. 제품 전체의 Jev 전환과 실제 설치 검증은 미완료입니다.

공개 개발과 오픈소스 배포를 목표로 합니다. 기준 feature 소스의 프로젝트 라이선스와 패키지 notices는 배포 전 확정·검토가 필요한 상태입니다.

## 제품 개요

### 해결하려는 문제

사무직·데이터 분석가·경영자·개발자가 각자의 도구와 개인 문맥을 활용하는 비서를 갖는 것이 목표입니다. 사용자가 RAG 저장소나 workflow를 직접 설계하지 않아도 연결한 도구에서 자료를 찾고, 필요한 조건을 확인하고, 실행 결과를 검토할 수 있어야 합니다. 지원 업무는 공통 엔진의 인수 시나리오로 확장하며 직업별 고정 흐름을 별도 제품으로 만들지 않습니다.

첫 사례에서는 숫자 자료와 자연어 규정을 함께 다룹니다. 원본 누락, 잘못된 분류, 검토되지 않은 예외와 출처 없는 집계가 신뢰도를 떨어뜨리므로 원본 행과 규정 근거까지 따라갈 수 있는지 우선 검증합니다.

### 첫 구현과 인수 범위

- 입력: Excel의 네이티브 셀과 텍스트를 추출할 수 있는 규정 PDF
- 처리: 검증된 후보 안에서 Jev가 판단하고, 코드가 실행·권한·계산을 검증
- 검토: 불확실한 분류와 예외를 사람이 확인
- 출력: 원본과 근거를 보존한 XLSX·PDF
- 호환성: 기존 PDF 보고서 기능을 유지하면서 새 흐름을 별도로 검증

Gmail·Slack·DB·파일 등 연결 기능은 기존 제품 범위에 있습니다. 더 넓은 업무는 도구 카탈로그와 공통 엔진을 통해 확장할 목표이며, Excel·PDF가 제품의 최종 한계는 아닙니다. 다만 스캔 PDF OCR, 개발 업무 실행과 모든 연결 도구의 모든 동작은 이번 첫 인수 완료로 검증되는 범위가 아닙니다.

### 연결과 검색 경험

목표 설정 경험은 Jev, 문안용 LLM CLI와 필요한 도구를 연결하는 것입니다. 실제 계정·인증·권한 단계는 필요하고, 현재 모든 연결이 한 번에 완료되는 UX는 검증되지 않았습니다. 연결 도구의 검색 API를 우선 사용하고, 내부 색인·벡터 검색이 필요하더라도 사용자에게 필수 RAG 구축 작업을 요구하지 않는 방향입니다.

Jev가 찾을 자료·도구·다음 행동을 판단하고 코드가 조회·실행하며 LLM이 문안을 만들 수 있습니다. 검색 자체가 없어지는 것은 아닙니다. AX와 LLM agent·RAG 방식의 정확도·시간·토큰·비용은 [공정 비교 계획](validation-release.md#ax와-llm-agent-rag-비교)으로 검증하며 우위를 전제하지 않습니다.

### 역할과 결정

- **제품 책임자:** 제품 방향, 중요한 기술 선택, 인수 판단, main 병합과 정식 릴리스 승인. Windows에서 직접 사용 테스트
- **개발·검증 담당:** 구현, 일상적인 수정, 병렬 작업 조정, Linux 빌드·검증, 증거와 문서 유지
- **공동 검토:** 데이터 의미, 검토 정책, 호환성에 영향을 주는 변경. 확정되지 않은 정책은 구현자가 임의로 정하지 않음
