# AX Studio 요구사항과 인수 기준

제품 목표는 여러 직업과 업무에 적용되는 연결 도구 기반 개인 비서입니다. Excel과 규정 PDF의 예외 검토·집계·보고서는 첫 검증 대상입니다. 아래 인수 기준은 완료를 판정할 조건이며, 현재 모두 충족했다는 뜻은 아닙니다. 구현과 검증 상태는 [진행과 위험](progress-risks.md), 실행 증거는 [검증과 릴리스](validation-release.md)에 기록합니다.

## 확정된 제품 요구사항

| ID | 요구사항 | 인수 기준 |
| --- | --- | --- |
| R01 | Jev가 제한된 판단을 수행 | host가 발급한 유효 후보만 선택 가능. 알 수 없는 선택, 서비스 오류, 불확실성은 질문 또는 안전한 중단으로 처리 |
| R02 | 코드는 실행과 검증을 소유 | 입력 타입·의존성·허용 대상·권한·승인을 검증하고, 계산과 파일 출력을 결정적으로 실행 |
| R03 | LLM은 문안에만 사용 | 설명·요약·보고서 문안은 생성할 수 있지만 도구·대상·필터·권한·승인 결정을 만들지 않음. Jev 실패 시 LLM 판단으로 대체하지 않음 |
| R04 | Excel 원본과 출처 보존 | 계산용 정규화 값과 원본 값의 차이를 유지. 원본 파일 식별, 시트, 물리적 행·열과 안정적인 행 식별자를 결과까지 추적 |
| R05 | 첫 규정 입력은 텍스트 PDF | 규정 텍스트와 출처가 확인되어야 진행. 스캔만 있는 PDF, 추출 실패나 부족한 근거를 임의 규정으로 보충하지 않음 |
| R06 | 예외와 불확실성은 사람 검토 | 분류 이유·원본 행·규정 근거를 보여주고 검토 상태를 기록. 미해결 항목을 포함한 결과의 취급은 확정된 검토 정책을 따름 |
| R07 | 집계와 출력의 완전성 검증 | 읽기 제한, 빠진 시트·행, 불완전한 데이터가 있으면 완전한 결과로 표시하거나 전체 집계를 발행하지 않음. XLSX·PDF의 행 수와 값은 독립 기준값으로 확인 |
| R08 | 기존 보고서 호환성 유지 | 새 Jev 전용 흐름을 별도로 구현. 기존 빈 양식·완성 예시 기반 PDF 경로를 제거하지 않고 회귀 검증 |
| R09 | 사용자가 계획을 검토 | 입력, 단계, 근거, 검토 지점과 출력 범위를 실행 전에 확인. 필요한 조건이 빠지면 질문 |
| R10 | 문서와 그림의 상태 일치 | 구현·제안·미검증을 구분. FigJam의 연결선·글자·정렬·넘침을 변경 후 화면으로 확인 |
| R11 | 낮은 설정 부담의 개인 비서 | Jev·LLM CLI·도구 연결과 필요한 인증·권한으로 시작하는 UX를 검증. 사용자가 RAG 저장소나 workflow를 미리 설계해야 하는 흐름을 요구하지 않음 |
| R12 | 공통 엔진으로 다양한 업무 확장 | 대화·검색·계획·실행·검증의 공통 경계를 유지. 각 업무는 실제 지원 도구·권한·개인 문맥과 인수 증거로 지원 범위를 표시 |
| R13 | 도구별 도메인 지식으로 정확히 연결 | 도구의 용도·전제·데이터 의미·입출력·완전성·부작용을 판단과 검증에 활용. 사용자 업무 규칙을 도구 의미로 추정하지 않음 |

R01–R03의 핵심 원칙과 R04–R09의 첫 제품 흐름은 제품 방향으로 확정되었습니다. 별도 흐름과 기존 기능 보존은 2026-10-01 09:16 UTC에 승인되었습니다. 범용 개인 비서와 낮은 설정 부담은 같은 날 후속 대화에서 명확해졌습니다. 구체적인 필드 계약, 개인 문맥·도구 확장과 화면은 구현·검토가 남아 있습니다.

R13의 도구별 지식 필요성은 같은 날 요청되었습니다. 지식 registry의 필드·저장 형식·갱신·버전 계약은 제안 단계이며 도구별 실제 검증이 필요합니다.

원본 보강의 현재 구현은 SheetJS가 반환하는 scalar 값과 물리적 좌표입니다. 수식·표시 서식·오류 셀 메타데이터와 CSV는 이번 수정 범위에 포함하지 않았습니다. R04의 제품 인수에서는 업무에 필요한 원본 의미가 이 범위로 충분한지 별도로 확인합니다.

## 업무 확장 인수안

다음은 같은 엔진을 평가할 시나리오 제안이며 모두 현재 지원·검증됐다는 뜻은 아닙니다. 각 시나리오에서 정확한 자료와 허용된 도구·대상·결과를 먼저 고정합니다.

| 업무 맥락 | 대표 시나리오 | 인수 핵심 |
| --- | --- | --- |
| 사무 업무 | Excel·규정 PDF 예외 분류와 검토 후 보고서 | 원본·규정 근거, 검토 상태, 정확한 집계 |
| 데이터 분석 | 연결 DB·표에서 조건 조회·비교·정렬·내보내기 | 전체 source coverage, 조건·단위·기준값, 재현성 |
| 경영·팀 운영 | 연결 문서·메일·일정에서 현황과 후속 업무 정리 | 사실과 제안 구분, 출처, 대상·내용 검토와 필요한 승인 |
| 개발 업무 | 연결한 저장소·이슈에서 근거 검색과 문제 분석 | 파일·revision 근거, 허용된 작업 범위, 실제 검증과 미검증 구분 |

연결이 있다고 모든 쓰기·전송·개발 실행이 허용되는 것은 아닙니다. 역할별 시나리오에서도 host의 권한·검증·승인 경계를 동일하게 적용합니다.

## 첫 흐름의 인수 시나리오

### 정상 완료

1. 알려진 전체 행 수를 가진 합성 Excel과 텍스트 규정 PDF를 지정한다
2. 모든 대상 시트와 행이 읽혔는지 확인한다
3. 원본 값, 계산용 값, 규정 버전과 근거 위치를 확인할 수 있다
4. Jev가 유효한 후보 안에서 분류하고, host가 결과를 검증한다
5. 사람이 예외와 불확실한 항목을 검토한다
6. 검토 상태에 따른 집계와 출력 정책을 적용한다
7. XLSX와 PDF에서 빠진 행·중복 행·합계 오류가 없는지 독립적으로 확인한다
8. 같은 입력·규정·확정된 결정·검토 기록을 재실행하면 동일한 업무 결과를 재현한다

모델의 새로운 호출이 항상 같은 판단을 한다고 가정하지 않습니다. 재현성은 저장된 유효 결정과 입력 버전, 검토 기록을 기준으로 검증합니다.

### 안전한 중단과 재검토

| 사례 | 요구되는 결과 |
| --- | --- |
| 행 제한보다 원본 데이터가 많음 | 부분 읽기를 표시하고 전체 집계를 거부 |
| 시트 제한 때문에 일부 시트가 제외됨 | 누락을 명시하고 완전한 워크북으로 취급하지 않음 |
| `00123`, 공백, 빈 행, 중복 업무 ID | 원본 의미와 물리적 위치를 잃지 않고 개별 행을 추적 |
| 원본 파일 또는 규정 변경 | 이전 검토 기록을 새 버전에 그대로 적용하지 않고 재검토 여부를 판정 |
| 텍스트가 없는 PDF 또는 근거를 찾을 수 없음 | 질문 또는 중단. 확인되지 않은 규정을 생성하지 않음 |
| 유효 후보 밖의 선택·잘못된 타입·순환 의존 | host 검증에서 거부하고 실행하지 않음 |
| Jev 오류·시간 초과·불확실한 판단 | 오류나 검토 필요 상태를 표시. LLM 판단 fallback 없음 |
| 문안 출력으로 실행 대상·분기·승인 변경 시도 | 바인딩 검증에서 거부 |
| 검토 중 앱 종료·재시작 | 검토 상태와 증거를 복구하며 승인된 작업을 중복 실행하지 않음 |
| 보고서 공간 부족 | 행을 조용히 자르지 않고 중단 또는 검토된 확장 적용 |

## 구현 전에 확정할 정책

다음은 제품 책임자와 검토할 항목입니다. 현재 문서가 정책을 확정하지 않습니다.

- 분류의 정확한 범주, 검토 의무 대상과 검토 완료의 의미
- 미해결 예외를 최종 합계에서 제외할지, 별도 합계로 표시할지, 출력 자체를 막을지
- 금액 단위, 소수 자릿수, 반올림과 통화 혼합 처리
- 업무별 허용 오차와 분류 품질 목표, 대표 검증 데이터
- 규정 근거 표시의 최소 단위와 변경 시 검토 기록의 만료 기준
- 파일 크기·행 수·문맥 한도·시간·비용의 제품 기준

## 성능과 품질 목표

초기 대화에서 1–2초 수준의 반응 가능성이 가설로 제시됐지만, 전체 업무 시간으로 검증되지 않았습니다. 제품 성능 약속으로 사용하지 않습니다.

검증에서는 입력 규모와 전체 작업 시간을 함께 기록하고, Jev 호출 시간, 읽기·분류·검토·집계·출력 시간을 나눠 측정합니다. 분류 품질은 사람의 기준 라벨과 불확실성 처리, 보고서 품질은 독립 기준값과 원본 커버리지로 평가합니다. 목표 수치는 대표 작업과 정책 확정 후 정합니다.
