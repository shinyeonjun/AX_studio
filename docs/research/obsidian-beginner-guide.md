# 옵시디언(Obsidian) 초보 사용 가이드

조사일: 2026-09-28. 제품 기능과 가격은 Obsidian 공식 문서를 확인했다. 초보용 구성과 적합성 평가는 기능을 바탕으로 한 권고다.

## 한 줄 요약

Obsidian은 노트를 Markdown 형식의 일반 텍스트 파일로 내 컴퓨터에 저장하고, 노트끼리 링크해 지식과 기록을 연결하는 앱이다. 노트가 들어 있는 폴더를 **Vault(볼트)**라고 한다. 별도 계정이나 클라우드가 없어도 로컬에서 쓸 수 있고, 파일은 다른 텍스트 편집기로도 열 수 있다. [Vault 만들기](https://obsidian.md/help/vault), [데이터 저장 방식](https://obsidian.md/help/data-storage)

## 처음 시작하기

1. [공식 다운로드 페이지](https://obsidian.md/download)에서 PC 앱을 설치한다.
2. **Create new vault**를 눌러 `내 노트` 같은 이름으로 볼트를 하나 만든다. 처음에는 여러 볼트를 나누지 않아도 된다. 볼트는 일반 폴더이므로 찾기 쉬운 위치를 고른다. 볼트 안에 또 다른 볼트를 만들면 링크가 예상대로 동작하지 않을 수 있다. [볼트 만들기](https://obsidian.md/help/vault), [저장 방식과 볼트 주의사항](https://obsidian.md/help/data-storage)
3. `Ctrl+N`으로 노트를 만들고 제목을 입력한다. 본문은 일반 글처럼 적고, `# 제목`, `- 목록`, `**굵게**` 같은 Markdown 표시를 필요할 때만 쓴다. [첫 노트 만들기](https://obsidian.md/help/create-note), [기본 서식](https://obsidian.md/help/syntax)
4. 관련 주제가 나오면 `[[주제 이름]]`을 입력해 노트에 링크한다. 아직 없는 노트도 링크를 먼저 만들어 두고 나중에 채울 수 있다. [노트 연결하기](https://obsidian.md/help/link-notes)
5. 노트 오른쪽의 **Backlinks(역링크)** 창에서 현재 노트를 언급한 다른 노트를 찾고, **Search**로 내용이나 파일명을 검색한다. `Ctrl+Shift+F`는 검색 창을 연다. [역링크](https://obsidian.md/help/plugins/backlinks), [검색](https://obsidian.md/help/plugins/search)

이 다섯 가지만 익히면 기록을 시작할 수 있다. Obsidian의 핵심은 복잡한 분류 체계를 먼저 설계하는 것보다, 적을 때 연결하고 필요할 때 검색하는 데 있다.

## 일상적인 사용 흐름

- **빠른 기록:** 생각, 회의 메모, 읽은 내용 등을 각자 찾기 쉬운 제목의 노트로 적는다.
- **연결:** 본문에서 관련 개념·사람·프로젝트를 `[[이름]]`으로 잇는다. 예를 들어 회의록에서 `[[프로젝트 알파]]`를 연결해 두면, 프로젝트 노트에서 역링크를 통해 회의록을 되찾을 수 있다.
- **다시 찾기:** 먼저 검색하고, 특정 노트에서 그 노트를 언급한 기록을 찾고 싶을 때 역링크를 본다.
- **하루 기록이 필요할 때:** 기본 **Daily notes** 플러그인은 오늘 날짜의 노트를 열거나 만든다. 일기, 할 일, 하루 동안 발견한 내용을 남길 때 켠다. 매일 노트를 쓰지 않는다면 꺼두어도 된다. [Daily notes](https://obsidian.md/help/plugins/daily-notes)
- **반복 양식이 생기면:** 기본 **Templates** 플러그인으로 회의록·독서 기록 등의 틀을 만들어 삽입한다. 템플릿 폴더 설정 후 `Templates: Insert template` 명령을 사용한다. [Templates](https://obsidian.md/help/plugins/templates)

## 폴더, 태그, 속성은 어떻게 다른가

실용적으로는 **폴더를 큰 보관 위치**, **태그를 여러 노트에 걸치는 주제표시**, **속성(Properties)을 날짜·상태 같은 구조화 정보**로 생각하면 쉽다. Obsidian은 볼트를 실제 폴더와 파일로 저장하고, 태그로 관련 노트를 검색하며, 속성은 텍스트·날짜·숫자·체크박스 등으로 관리한다. [저장 방식](https://obsidian.md/help/data-storage), [태그](https://obsidian.md/help/tags), [속성](https://obsidian.md/help/properties)

처음에는 폴더를 꼭 만들지 않아도 된다. 필요하면 `Daily`, `Projects`, `Reference` 정도로 시작하고, `#업무`, `#아이디어`처럼 실제로 반복해서 찾을 기준에만 태그를 붙인다. 속성은 날짜나 진행 상태처럼 나중에 검색·정리할 값이 생겼을 때 추가한다. 세 분류 체계를 모두 처음부터 촘촘하게 만들면 기록보다 관리가 일이 될 수 있다.

## 그래프와 플러그인

**Graph view(그래프 보기)**는 노트를 원으로, 내부 링크를 선으로 보여주는 시각화다. [그래프 보기](https://obsidian.md/help/plugins/graph) 직접 만든 링크가 많아질수록 연결 지도를 볼 수 있지만, 자동으로 내용의 의미를 분석해 관계를 찾아주는 기능으로 이해하면 안 된다.

**Core plugins(핵심 플러그인)**은 Obsidian 팀이 포함해 제공하는 기능이며 일부는 설정에서 켜야 한다. 검색, 역링크, 템플릿, Daily notes, 그래프 보기가 여기에 속한다. **Community plugins(커뮤니티 플러그인)**은 외부 개발자가 만든 확장이다. 커뮤니티 플러그인은 컴퓨터 파일에 접근하거나 인터넷에 연결할 수 있으므로, 필요한 기능이 분명해지기 전에는 기본 제한 모드를 유지하고 설치를 미루는 편이 안전하다. [핵심 플러그인](https://obsidian.md/help/plugins), [플러그인 보안](https://obsidian.md/help/plugin-security)

## PC와 휴대폰, 동기화와 백업

노트는 기본적으로 현재 기기의 로컬 볼트에 있다. iOS와 Android용 앱도 있지만, PC와 휴대폰에서 같은 노트를 보려면 별도의 동기화 방식을 설정해야 한다. Obsidian Sync가 공식 동기화 옵션이며, 다른 파일 동기화 서비스도 사용할 수 있다. 다만 Obsidian Sync와 다른 클라우드 동기화 서비스를 동일한 볼트에 동시에 적용하면 충돌이 날 수 있다고 공식 문서는 경고한다. [기기 간 동기화](https://obsidian.md/help/sync-notes), [Sync 소개](https://obsidian.md/help/sync)

2026-09-28 확인 기준, 앱은 무료이고 계정 없이 로컬에서 시작할 수 있다. Sync는 선택형 유료 서비스다. Standard는 연간 결제 기준 월 $4 또는 월별 결제 월 $5이며, Plus는 각각 월 $8/$10이다. Plus는 저장 용량과 버전 기록 한도가 더 크다. 가격·한도는 바뀔 수 있으므로 결제 전 [공식 가격표](https://obsidian.md/sync)를 확인한다. [공식 가격 안내](https://obsidian.md/pricing)

**동기화는 백업이 아니다.** 삭제나 손상이 여러 기기에 전파될 수 있으므로, 중요한 노트는 별도 위치에 정기적으로 복사하는 백업도 마련한다. [공식 백업 안내](https://obsidian.md/help/backup)

## 처음 해볼 구성과 적합성

우선 PC에 볼트 하나를 만들고, 검색·역링크를 켜서 평소 쓰는 노트를 적어 본다. 하루 기록이 필요하면 Daily notes를, 반복 양식이 생기면 Templates를 추가한다. 커뮤니티 플러그인과 동기화는 실제 필요가 생긴 뒤 결정한다. 이 구성이 초기 설정 부담을 낮춘다는 점은 공식 기능 구성을 바탕으로 한 권고다.

여러 주제의 기록을 오래 모으고, 나중에 서로 연결해 다시 찾고 싶다면 Obsidian의 링크·역링크·일반 Markdown 파일 구조가 유용할 가능성이 높다. 반대로 짧은 메모 몇 개만 적고 끝내거나, 팀 공동 편집·업무 권한 관리가 우선이라면 설정과 파일 관리가 오히려 번거로울 수 있다. 이는 제품의 공식 보장이라기보다 기능과 사용 방식에 따른 적합성 판단이다.
