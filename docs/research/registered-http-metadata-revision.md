## R1: messages and revision stay together

The renderer's existing messages state now carries its transcript revision in one snapshot object. Load, refresh, initial/final save receipts, main-persisted reply loads, conflict reloads and resets publish that whole pair through a small helper. The message array and its top-level message objects are copied and frozen. A send callback captures one pair from its render; it never attaches a later mutable ref token to those older messages. Speculative display replacements carry no persisted token, so a queued old optimistic replacement cannot borrow the current state revision either. The legacy ref remains for compatible callers and observations, while those callers capture their pair when actions are created. Ordinary final saves retain their previously correct captured initial-save revision.

A retained callback therefore submits its older token and conflicts before command dispatch. Current authoritative content is reloaded, unsaved input is retained for review, and there is no automatic retry. Four regressions extend `useDiscovery.test.ts` for refresh, conflict reload, a newer ordinary C turn and a speculative snapshot without a persisted revision. They also create another callback from the old render after the ref has advanced, then verify that a genuinely current render preserves B/C and appends D once. These tests exercise actual store CAS and renderer helpers; the unchanged independent IPC probe exercises the real trusted handler, service and main publisher.

Shared edits are limited to `useWorkspaceChat.ts`, workspace-chat context contracts, load/lifecycle/message actions and new `transcript-snapshot.ts`. The shared-file impact was communicated before these edits. No UI worker commits are combined, and deletion/draft/confirmation reconciliation still requires review of the eventual combined tree.

## R2: reject whole raw entries before parsing

The local adapter filters each raw stored operation object and its associated label before `parseHttpEndpoints` can trim or deduplicate paths. Parsed operations now come only from those accepted objects. A later safe sibling cannot authorize an earlier rejected object's label. Accepted paths keep their own exact identity and label; dropped entries still produce filtered/incomplete local coverage. Generic HTTP parsing and legacy dispatch are unchanged.

Two Core regressions cover control-prefixed and whitespace-padded unsafe-first duplicates. HTTP-13 adds both collisions before the safe sibling, so approved evidence, readable/debug replies, the main transcript, evaluator requests and progress must exclude the rejected labels. It remains one of the original 13 rows; no extra study variant or model-quality case is introduced.
